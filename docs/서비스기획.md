# 핵심 기능

---

## 기능1

게시글 작성 후 매칭 기능

실시간으로 참여하는 기능 (소개팅 어플 처럼)

## 기능2

마이페이지 (로그인, 로그아웃, 회원탈퇴)

## 기능3

커뮤니티(게시글, 후기, CRUD)

방명록 매칭 후기 (마이페이지에 작성)

## 기능4

위치 기반 주변 매칭

매칭 후 대화방

## 기능5

초기에는 실시간 매칭 구현 우선

인원 분류 (소규모, 대규모)

- 식사 날짜/시간
- 식당, 지역
- 모집 인원
- 모집 제목/설명
- 모집 상태: 모집중/마감/완료

## 기능6

AI 식당 추천 (Spring AI)

## 기능7

가입 후 선택형 성향 온보딩 및 성향 기반 매칭 보조 랭킹

- 자가 응답 기반 식사·대화 성향과 원하는 상대방 선호 중요도를 분리 관리
- 위치·시간·인원 하드 필터 이후 결정론적 호환도 점수로 정렬
- Spring AI 임베딩은 자유 서술 성향의 보조 점수와 추천 사유 생성에만 사용
- AI 장애 또는 미응답 사용자도 기본 매칭 가능

## 기능8

- 관리자 계정 구현 (좀 더 고민)

# 기술 스택

## BE

| **구분** | **추천 스택** | 역할 | 선택 이유                                                                            |
| --- | --- | --- |----------------------------------------------------------------------------------|
| Cache / State | Redis | 매칭 대기열, 캐시, 임시 상태 | 매칭 대기열 및 일시적인 매칭 상태처럼 빈번하게 변경되는 데이터를 빠르게 처리하고, TTL을 활용해 임시 데이터를 효율적으로 관리하기 위해 선택 |
| BaaS | Spring Boot | 서버 | REST API 개발과 비즈니스 로직 구현을 위한 백엔드 핵심 프레임워크로 선택                                     |
| Database | Supabase PostgreSQL | 데이터 저장 | Supabase의 관리형 PostgreSQL을 Spring Data JPA로 연결하고 모든 서비스 데이터 접근은 Spring Boot API를 통해 처리 |
| Auth | Spring Security | 회원가입/로그인/JWT 발급·검증/접근 제어 | 이메일·비밀번호 인증, 카카오·Google OAuth2 로그인, JWT 발급·갱신·폐기 및 API 인가를 Spring Security에서 직접 처리 |
| Monitoring | Prometheus, Grafana | 서버 상태/성능 관찰 | 서버 부하 확인용                                                                        |
| **API** | Springdoc OpenAPI / Swagger | API 문서화 | 개발 단계에서 쉽고 빠른 문서화/테스트 가능                                                         |
| Chat | WebSocket + STOMP | 실시간 채팅 | WebSocket은 매칭 이후 사용자 간 실시간 채팅 기능을 제공하기 위해 선택                                     |
| Location | Kakao Maps + PostGIS | 구 단위 활동지역 선택, 지도 핀 지정, 거리/반경 검색 | Geolocation API에 의존하지 않고 선택 구의 대표 좌표로 지도를 연 뒤 사용자가 확정한 핀을 기준으로 매칭하기 위해 선택 |
| Personality Matching | Spring AI + pgvector | 자유 서술 성향 임베딩과 보조 랭킹 | 정형 성향은 애플리케이션의 버전된 호환도 공식으로 계산하고, AI는 하드 필터 이후의 제한된 보조 점수로만 활용 |

# 문제 정의

---

## 문제요약

1인 가구와 사회적 고립의 증가로 인해 함께 식사하며 자연스럽게 사람을 만날 기회가 감소하고 있으며, 기존의 소개팅·커뮤니티 서비스는 부담이 커 가볍게 식사를 매개로 교류할 수 있는 연결 수단이 부족하다.

## 해결방안

지역·시간·식사 목적을 기반으로 혼밥러를 1:1 또는 1:N으로 매칭하여, 부담 없이 함께 식사하고 자연스럽게 교류할 수 있는 기회를 제공한다.
