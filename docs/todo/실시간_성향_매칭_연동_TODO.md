- [ ] 생성 응답에 `requestId`, `status`, `expiresAt`을 반환한다.

- [ ] Redis 값에는 상세 자유 서술, JWT, OAuth 식별자 또는 정밀 위치 로그를 포함하지 않는다.

- [ ] `GET /matches/realtime/requests/me`에서 DB와 Redis 불일치를 안전하게 복구한다.

## 6. 성향 데이터 조립과 랭킹

- [ ] 요청자의 카드 점수와 요청 시점 `preference_snapshot`을 랭킹 입력으로 변환한다.
- [ ] 후보자의 현재 확정 카드 점수와 태그를 일괄 조회하여 N+1 쿼리를 방지한다.
- [ ] 요청 희망 태그와 후보 확정 태그를 `DesiredPersonalityTagScoreCalculator`에 전달한다.
- [ ] 요청 희망 설명 임베딩과 후보 자기 스타일 임베딩의 모델·차원·문서 버전 계열을 검증한다.
- [ ] 하드 필터 통과 후보에게만 `PersonalityCompatibilityCalculator`를 호출한다.
- [ ] 성향 계산이 가능한 후보는 최종 점수 내림차순으로 정렬한다.
- [ ] 성향 점수가 없는 후보도 탈락시키지 않고 기본 조건 순서로 fallback한다.
- [ ] 동점 후보의 정렬 기준을 거리, 대기 시작 시각, 요청 ID 순으로 고정한다.
- [ ] 응답에는 최종 점수, 상위 일치 태그와 사용자용 사유만 포함한다.
- [ ] 원본 설문 답변, 자유 서술, 임베딩 벡터, 차원별 내부 점수는 상대방에게 노출하지 않는다.

## 7. 매칭 확정과 동시성

- [ ] 후보 선택 시 양쪽 Redis 상태를 원자적으로 `CONFIRMING`으로 전환한다.
- [ ] 동시에 여러 요청이 동일 후보를 선택하지 못하도록 분산 락 또는 Lua 스크립트를 적용한다.
- [ ] 수락 성공 시 두 `MatchRequest`, `Match`, 정확히 두 `MatchParticipant`, `ChatRoom`을 하나의 DB 트랜잭션으로 저장한다.
- [ ] 거절·응답 시간 초과 시 후보 요청을 정책에 따라 대기열로 복귀시키고 `rejectCount`를 갱신한다.
- [ ] 일부 저장 실패 시 Redis 상태와 DB 상태를 복구한다.
- [ ] 매칭 확정 결과를 인증된 사용자 전용 STOMP 큐로 전달한다.

## 8. 프론트엔드 연동

- [ ] 매칭 요청 화면에 희망 상대 태그 3~5개 선택 UI를 연결한다.
- [ ] 선택 개수, 중복 선택, 지원하지 않는 태그를 클라이언트에서도 안내한다.
- [ ] 최대 300자의 선택형 희망 상대 설명 입력을 연결한다.
- [ ] 지도 핀·구 코드·식사 시간·음식 카테고리와 성향 입력을 하나의 요청으로 제출한다.
- [ ] 제출 전에 CSRF 토큰을 발급받고 인증 쿠키를 포함한다.
- [ ] 대기·취소·만료·확인 중·매칭 완료 상태를 화면에 반영한다.
- [ ] AI/성향 데이터가 없어도 기본 매칭이 가능하다는 안내를 제공한다.

## 9. 보안·개인정보·Fallback

- [ ] 희망 설명, 자기소개, 임베딩 입력·출력과 벡터를 애플리케이션 로그에 남기지 않는다.
- [ ] 정밀 핀 좌표를 매칭 확정 전 상대방 응답이나 WebSocket 메시지에 노출하지 않는다.
- [ ] 임베딩 장애, Redis 장애, 성향 미설정 상태별 fallback과 사용자 오류 응답을 구분한다.
- [ ] AI 또는 임베딩 장애 시 정형 점수를 100%로 재정규화한다.
- [ ] 정형 성향도 없으면 위치·시간 등 하드 필터 결과만으로 매칭을 계속한다.
- [ ] LLM 또는 임베딩 점수만으로 후보를 탈락시키지 않는다.
- [ ] 사용자 탈퇴·위치 동의 철회·매칭 취소 시 대기 데이터와 정책상 삭제 대상 파생 데이터를 제거한다.

## 10. 테스트와 문서 동기화

- [ ] `SIMILAR`/`COMPLEMENTARY`, 중요도 0, 경계 점수 0·100을 테스트한다.
- [ ] 태그 전부 일치·일부 일치·불일치·후보 태그 없음 테스트를 작성한다.
- [ ] 임베딩 동일·직교·반대 벡터와 모델·차원·버전 불일치 fallback을 테스트한다.
- [ ] 임베딩 반영 비율이 최종 점수의 20%를 넘지 않는지 테스트한다.
- [ ] 하드 필터 탈락 후보에 성향 계산기가 호출되지 않는지 테스트한다.
- [ ] 성향 프로필·선호·임베딩이 없는 사용자의 기본 매칭 성공을 테스트한다.
- [ ] 중복 대기, 동시 후보 선점, 취소, TTL 만료와 보상 처리 테스트를 작성한다.
- [ ] 타인의 자유 서술·원본 응답·임베딩·정밀 핀 접근을 차단하는 보안 테스트를 작성한다.
- [ ] PostgreSQL/PostGIS/Redis를 사용하는 통합 테스트를 작성한다.
- [ ] API 계약을 `API명세서.md`, 기능 동작을 `기능명세서.md`와 동기화한다.
- [ ] Java 변경 후 `gradlew.bat compileJava`와 `gradlew.bat test`를 실행한다.
- [ ] 테스트 로그에서 `CommandAcceptanceException`과 Hibernate 스키마 생성 오류가 없는지 확인한다.
