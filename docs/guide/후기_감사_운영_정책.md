# 후기 감사 이벤트 운영 정책

이 문서는 후기 오남용 대응을 위한 내부 감사 이벤트와 개인정보 최소화 기준을 정의한다. 감사 이벤트는 일반 API 응답이나 사용자 화면에 노출하지 않는다.

## 1. 감사 이벤트

후기 도메인은 다음 이벤트를 `ReviewAuditEvent`로 발행한다.

| 이벤트 | 발행 시점 | 결과 코드 |
| --- | --- | --- |
| `REVIEW_SUBMITTED` | 후기 저장 성공 후 DB 커밋 완료 | `SUCCESS` |
| `REVIEW_DUPLICATE_REJECTED` | 동일 매칭·상대에 대한 중복 제출 거부 | `REVIEW_ALREADY_SUBMITTED` |
| `REVIEW_PERIOD_EXPIRED` | 매칭 종료 후 7일이 지나 제출 거부 | `REVIEW_PERIOD_EXPIRED` |
| `REVIEW_REPORT_HANDLED` | 신고 처리 기능에서 처리 결과 확정 후 커밋 완료 | `REPORT_ACCEPTED`, `REPORT_REJECTED`, `REPORT_DISMISSED`, `REPORT_ESCALATED` |

성공 이벤트는 후기 저장 트랜잭션이 커밋된 뒤 발행한다. 중복·기간 만료 거부는 업무 결과 자체가 운영상 의미가 있으므로 예외로 인해 트랜잭션이 롤백되어도 즉시 발행한다.

## 2. 이벤트에 포함할 수 있는 값

이벤트에는 이벤트 종류, 결과 코드, 발생 시각, 키 버전, 그리고 다음 HMAC 가명 키만 포함한다.

- 계정 식별자: `actorKey`, `subjectKey`
- 매칭 식별자: `matchKey`
- 후기 식별자: `reviewKey`

다음 값은 이벤트·후기 감사 로그에 기록하지 않는다.

- 후기 원문 답변, 별점 원문, 신고 원문
- JWT, Refresh Token, OAuth Provider ID
- 이메일, 전화번호, 닉네임, 정밀 위치
- IP, User-Agent, 디바이스 식별 정보

현재 후기 MVP는 자유 서술형 답변을 받지 않지만, 이후 입력 항목이 늘어날 때도 동일한 금지 기준을 적용한다.

## 3. 가명 키와 키 회전

`ReviewAuditPseudonymizer`는 `user`, `match`, `review` 네임스페이스를 분리한 HMAC-SHA-256 결과를 운영 키로 사용한다. 이벤트에는 원본 UUID·숫자 ID 대신 `키 버전:해시` 형식의 가명 키가 들어간다.

운영 설정은 다음 환경변수로 주입한다.

```properties
REVIEW_AUDIT_PSEUDONYM_KEY=Secret Manager에서 주입하는 32바이트 이상 키
REVIEW_AUDIT_PSEUDONYM_KEY_VERSION=v1
```

- 키는 애플리케이션 저장소, DB, 일반 설정 파일에 기록하지 않고 Secret Manager에 보관한다.
- 키는 최소 90일 주기 또는 보안 사고 발생 즉시 회전한다. 회전할 때 키와 버전을 함께 교체한다.
- 이전 키는 해당 가명 로그를 조사해야 하는 기간에 한해 Secret Manager에 제한적으로 보관하고, 연관 로그 파기 시 함께 파기한다.
- 원본 식별자와 키를 결합해 조회할 수 있는 권한은 운영·보안·개인정보 담당 역할로 제한한다. 일반 애플리케이션 API와 개발자용 일반 로그 조회에는 이 권한을 부여하지 않는다.
- 키가 설정되지 않은 개발 환경은 프로세스 재시작 시 달라지는 임시 키를 사용한다. 운영 환경은 임시 키로 기동하지 않도록 배포 점검에서 필수 설정을 확인한다.

키 회전 후 버전이 달라진 로그는 기본적으로 서로 직접 결합하지 않는다. 이는 운영 추적 범위를 제한하기 위한 의도된 개인정보 최소화 동작이다.

## 4. 로그 보존·조회·파기

기술적 기본 보존 기간은 감사 로그 90일이다. 실제 보존 기간이 법령·사고 조사·내부 정책에 따라 달라질 경우 개인정보 담당자가 승인한 기간을 운영 로그 플랫폼에 적용한다.

`audit.review` 로거는 일반 애플리케이션 로그와 별도 대상으로 수집한다. 운영 로그 플랫폼은 다음 권한을 분리한다.

- 쓰기: 애플리케이션 실행 계정
- 조회: 승인된 운영·보안 담당자
- 보존 기간 변경·파기 정책 변경: 운영 책임자와 개인정보 담당자 공동 승인

애플리케이션 로그에는 후기 원문이나 인증 자격증명을 남기지 않는다. 일반 로그에는 필요한 집계 건수와 고정 오류 코드만 기록한다. 보존 기간이 끝난 감사 로그와 해당 키는 로그 플랫폼의 자동 파기 절차로 삭제하고, 별도 백업에 남아 있는 사본도 동일한 파기 일정으로 처리한다.

## 5. IP·User-Agent·디바이스 정보

후기 감사 이벤트는 IP·User-Agent·디바이스 정보를 수집하지 않는 것을 기본으로 한다. 장애 대응이나 부정행위 탐지 때문에 수집이 필요해지는 경우에는 구현 전에 개인정보 담당자와 아래 항목을 확정한다.

1. 구체적인 수집 목적과 최소 수집 항목
2. 처리의 법적 근거와 사용자 고지 필요 여부
3. 보관 기간과 자동 파기 방법
4. 조회 가능한 운영 주체와 접근 감사 방법
5. 파기 완료 확인 및 예외 보관 승인 절차

승인 전에는 웹 서버·프록시·APM 로그에 해당 정보가 남지 않는지도 함께 점검한다.
